# Лабораторная 1 — GPIO, вариант 1 «Светофор»

Стенд SDK-1.1MC.427. Обе части выполнены в одном приложении: универсальные
драйверы светодиодов/кнопки и собственный регистровый драйвер GPIO (способ 1).
В штатном цикле нет `HAL_Delay`, EXTI, RTOS и дополнительных таймеров.
Время читается через `HAL_GetTick()`, используется только SysTick.

## Запуск в STM32CubeIDE

1. Подключить питание стенда и кабель **DBG USB**. BOOT0 — штатное положение
   загрузки из Flash. Не использовать разъём USB приложения вместо DBG USB.
2. Установить WinUSB для **SDK 1.1M Debugger (Interface 0)**:
   [Zadig](https://zadig.akeo.ie/) → `Options → List All Devices` → выбрать
   именно Interface 0 (`USB\\VID_0403&PID_6010&MI_00`) → WinUSB → Install Driver.
   **Не заменять драйвер Interface 1:** это отдельный канал UART.
   Для этой работы он не нужен. Не выбирать родительское составное USB-устройство.
3. В CubeIDE: `File → Import → General → Existing Projects into Workspace`.
   Root directory: `C:\Users\admin\Design-of-computing-systems\lab1`.
   Выбрать `lab1`, снять `Copy projects into workspace`, нажать Finish.
4. `Project → Build Project` (Ctrl+B). Получится `Debug/lab1.elf`.
   Это готовый проект с ручной настройкой GPIO и тактирования; генерация CubeMX
   для запуска не нужна, `.ioc` намеренно отсутствует.
5. После установки драйвера проверить и прошить из PowerShell в корне репозитория:

   ```powershell
   python lab1/tools/board.py probe
   python lab1/tools/board.py flash
   ```

   `flash` программирует собранный CubeIDE ELF, проверяет Flash и перезапускает
   контроллер. `probe` показывает идентификатор и размер Flash, кратковременно
   останавливая ядро. Прошивка начинается с красного.

На 14.09.2026 обе USB-функции обнаружены, но имели код ошибки Windows 28
(драйвер отсутствует). OpenOCD сообщил `LIBUSB_ERROR_NOT_FOUND`.
Сборка и программные тесты проверены; физическое выполнение пока не подтверждено.
Актуальный протокол — [VALIDATION.md](docs/VALIDATION.md).

## Отладка в CubeIDE

Встроенный программатор — **FT2232/JTAG**, не ST-LINK. Использовать `SDK11M.cfg`.

В `Run → Debug Configurations → STM32 C/C++ Application` создать конфигурацию
для проекта `lab1`, C/C++ Application: `Debug/lab1.elf`.
Вкладка Debugger: выбрать **OpenOCD**, интерфейс **JTAG** и пользовательский
configuration script `SDK11M.cfg` вместо автоматически создаваемого ST-LINK script.
В CubeIDE 1.9 поле выбора сервера называется `Debug probe`; вариант обычно
называется `ST-LINK (OpenOCD)`, но сам адаптер определяет пользовательский cfg.
Выбрать `User Defined` для Configuration Script и указать полный путь к cfg.
Проверить, что command line сервера содержит этот файл, а не `stlink-dap.cfg`.
В Startup оставить загрузку исполняемого файла и остановку на `main`.

Если GUI не позволяет задать сторонний адаптер, запустить сервер отдельно:

```powershell
python lab1/tools/board.py debug
```

Он остаётся запущенным. Подключить **GDB Hardware Debugging** к `localhost:3333`
с ARM GDB из CubeIDE, ELF `Debug/lab1.elf`. Команды GDB:
`monitor reset halt`, `load`, `tbreak main`, `continue`.
Не запускать два OpenOCD одновременно. Завершить сервер через Ctrl+C.

Полезные Expressions: `traffic.state`, `traffic.request`, `traffic.since`,
`button.pressed`, `uwTick`, `lab1_fault`, `GPIOD->ODR`, `GPIOC->IDR`.
После остановки на main нажать **Resume (F8)**: на breakpoint программа не работает.
Проверять временные интервалы без остановок отладчика.

## Что должно происходить

| Фаза | Время | Действие кнопки |
|---|---:|---|
| Красный | 12 с | Сократить текущий красный до 3 с от его начала |
| Зелёный | 3 с | Игнорировать новое нажатие |
| Мигающий зелёный | 3 с, переключение каждые 500 мс | Запомнить запрос |
| Жёлтый | 1 с | Запомнить запрос |

После жёлтого снова красный. Если запрос сохранён, ближайший красный длится
3 с. Нажатие после истечения этих 3 с переключает красный на зелёный при
подтверждении нажатия. На границе ровно 3 с также происходит переход.
Следующий красный снова 12 с, если не было нового нажатия.
Повторные нажатия не перезапускают отсчёт. Удержание не порождает повторов.
Зажатая при включении кнопка считается исходным состоянием: её нужно отпустить
и нажать заново. Защита от дребезга требует 30 мс стабильного уровня.

Длительности заданы в `Core/Inc/traffic.h`, дребезг — в `Core/Inc/board.h`.
3 с зелёного, 3 с мигания и 1 с жёлтого выбраны для демонстрации;
соотношение красного/зелёного 4:1 и сокращение до ¼ — требования варианта.

## Подключение GPIO

Сверено по [схеме производителя](docs/SDK1.1M.pdf), страницы PDF 2 и 3.

| Сигнал | GPIO | Настройка / уровни |
|---|---|---|
| Зелёный GLC | PD13 | Push-pull, low speed, 1 = включён |
| Двухцветный YARC | PD14 | Push-pull, low speed |
| Двухцветный YCRA | PD15 | Push-pull, low speed |
| Кнопка nBTN | PC15 | Input, no pull; внешний R11 к 3,3 В, 0 = нажата |

Красный: PD15=1, PD14=0. Жёлтый: PD15=0, PD14=1.
Одинаковые уровни на PD14/PD15 выключают двухцветный индикатор.
Все три сигнала меняются одной записью `BSRR`; назначение остальных пинов
порта сохраняется. Никаких контактов отладки PA13/PA14/PA15/PB3/PB4 приложение не меняет.
PC15 не используется для LSE/RTC.

Тактирование: внутренний **HSI 16 МГц**, PLL выключен, AHB/APB1/APB2 = 16 МГц,
Flash latency 0. Этого достаточно для GPIO. Схема показывает STM32F427VIT6;
проект использует общее семейство `STM32F427xx` и консервативный диапазон памяти:
1 МиБ Flash, 192 КиБ SRAM, 64 КиБ CCM. Он подходит также STM32F427VGT6 из задания;
дополнительная Flash варианта VI не используется.

## Структура и вторая часть

* `gpio_driver.c/.h` — собственные структуры, настройка и чтение конфигурации,
  одиночные и групповые чтение/запись, контроль LCKR и безопасного порядка записей.
* `led.c/.h` — универсальный банк индикаторов одного GPIO-порта, без цветов/таймингов.
* `button.c/.h` — автомат подавления дребезга логического входа, без привязки к пину.
* `traffic.c/.h` — вся прикладная логика светофора.
* `main.c`, `board.h` — соединяют драйверы и приложение, задают разводку стенда.
* `Drivers/` — CMSIS/HAL для запуска, часов и SysTick; стандартный GPIO оставлен
  для изучения. Само приложение не вызывает `HAL_GPIO_*` или `LL_GPIO_*`.

Описание регистров, порядка повторной инициализации и сравнение с HAL/LL:
[DEFENSE.md](docs/DEFENSE.md). Ограничения передачи активных AF-сигналов
описаны явно: это не операция, которую универсальный GPIO-драйвер может
согласовать с работающим периферийным устройством самостоятельно.

## Сборка и тесты без GUI

```powershell
python lab1/tools/build.py
python lab1/tools/build.py --test
python lab1/tests/run_tests.py
```

Первая команда создаёт `build/lab1.elf` и `build/lab1.bin` (это отдельная сборка,
не `Debug/lab1.elf`). Для её прошивки:
`python lab1/tools/board.py flash --elf lab1/build/lab1.elf`.
Скрипты находят инструменты CubeIDE в `C:/ST`. Для другой установки задать
`ARM_GCC_BIN`, `OPENOCD_EXE`, `OPENOCD_SCRIPTS`.
Для запуска тестов требуется Python-пакет `unicorn`; для сборки прошивки он не нужен.
Тесты выполняют реальный скомпилированный C-код ARM. Эмулятор моделирует
побочный эффект BSRR и контролирует порядок записей. Это не симулятор для способа 2:
вторая часть сдана как собственный драйвер в прошивке.

Лицензии и версии сторонних компонентов: [THIRD_PARTY.md](docs/THIRD_PARTY.md).
