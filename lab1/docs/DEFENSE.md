# Пояснения к защите

## Архитектура

В одном обороте main считываются время и вход кнопки, обновляются автомат
дребезга и автомат светофора, затем записывается требуемая комбинация выходов.
Каждая операция короткая и возвращает управление. Это кооперативная
псевдопараллельность: ожидание времени представлено состоянием, а не задержкой.
HAL_GetTick читает счётчик, который увеличивается обработчиком SysTick раз в 1 мс.
Остальные аппаратные прерывания приложение не включает. Обработчики fault —
диагностика ошибок ядра, а не механизм обработки кнопки.

Разность `(uint32_t)(now - since)` вычисляется по модулю 2^32, поэтому переход
счётчика через ноль не ломает интервалы 30–12000 мс. Цикл должен выполняться
регулярно; пропуск полного оборота счётчика (около 49,7 суток) не поддерживается.
Переход фазы отсчитывается от фактического выполнения, поэтому опоздание
главного цикла увеличивает фазу на это опоздание. При нормальном выполнении
оно мало относительно 1 мс; при остановке отладчиком интервалы не проверяют.
HSI имеет погрешность: миллисекунды здесь задаются локальным тактированием,
а не внешним эталоном точного времени.

Кнопка имеет candidate (последний сырой уровень), pressed (подтверждённое
состояние) и changed_at. Любая смена сырого уровня начинает 30 мс заново.
После устойчивости состояние принимается; true возвращается лишь для перехода
«отпущена → нажата». Освобождение также фильтруется. Драйвер кнопки можно
применить к любому логическому входу; инверсию active-low выполняет main.

Автомат светофора: RED → GREEN → BLINK → YELLOW → RED.
request ставится по событию нажатия во всех состояниях кроме GREEN.
В RED выбирается порог 3000 либо 12000 мс. При выходе из RED request сбрасывается.
При BLINK состояние лампы вычисляется из чётности полупериода; никаких отдельных
таймеров нет. Событие, совпавшее с переходом фазы, относится к фазе до перехода.

## Регистры GPIO (RM0090)

| Регистр | Назначение |
|---|---|
| RCC_AHB1ENR | Включает тактирование блока порта; после записи выполняется readback |
| MODER | По 2 бита: 00 input, 01 output, 10 alternate, 11 analog |
| OTYPER | По 1 биту: 0 push-pull, 1 open-drain |
| OSPEEDR | По 2 бита задают скорость фронтов выходного буфера, не частоту переключений программы |
| PUPDR | По 2 бита: 00 без подтяжки, 01 вверх, 10 вниз, 11 зарезервировано |
| IDR | Фактический цифровой уровень на ножке; может отличаться от ODR |
| ODR | Защёлка запрограммированных уровней выходов |
| BSRR | Младшие 16 бит устанавливают ODR, старшие сбрасывают; запись атомарна для порта |
| LCKR | Последовательность блокировки фиксирует настройки выбранных пинов до сброса |
| AFR[0], AFR[1] | По 4 бита на пин выбирают AF0–AF15 для пинов 0–7 и 8–15 |

Push-pull активно тянет выход и вверх, и вниз. Open-drain активно тянет только
вниз; при ODR=1 отпускает линию, для высокого уровня нужна подтяжка.
В аналоговом режиме цифровой входной тракт отключается. В AF источником
выходного сигнала становится периферийный блок. AFR сам по себе не включает AF:
нужно также MODER=10. Доступность AF и самого пина зависит от корпуса/модели.

`io_read` возвращает IDR & mask; `io_read_latch` — ODR & mask.
`io_write(port, mask, bits)` делает одну запись:
`BSRR = ((mask & ~bits) << 16) | (mask & bits)`.
Биты вне mask не изменяются. SET и RESET не пересекаются. BSRR записывается
присваиванием, а не `|=`: читать регистр команд для read-modify-write не нужно.

## Повторная инициализация

До записи проверяются маска, значения параметров, LCKR и условия передачи AF.
При ошибке возвращается статус, частичной настройки выбранных пинов не происходит.
`io_clock_enable` вызывается перед обращением к регистрам порта.

При входе в output сначала загружается требуемый уровень ODR через BSRR,
потом задаются электрические параметры и в последнюю очередь MODER. Иначе
на выход могло бы попасть старое значение ODR на время между двумя записями.
При output → output пин не переводится промежуточно во вход: выходной буфер
остаётся подключённым. Перед переключением open-drain → push-pull на уже
активном GPIO-выходе включается push-pull с прежней защёлкой, затем обновляется
защёлка — не появляется промежуток с отпущенным выходом из-за предзагрузки 1.
При выходе в input/analog сначала отключается выходной буфер, затем меняются
параметры. Обновление MODER выполняется целым словом с сохранением чужих полей.

Гарантия отсутствия программного импульса относится к GPIO-сигналам при
корректной электрической нагрузке; open-drain требует подходящей подтяжки.
Внешний конфликт драйверов или произвольная фаза активного AF не управляются ODR.
Поэтому прямые output → AF и активный AF → output/другой AF возвращают
`IO_HANDOFF_REQUIRED`. Сначала владелец периферии должен остановить её, затем
явно отпустить пин в input/analog и настроить новый режим. Повтор той же
конфигурации AF допускается. Нельзя обещать непрерывное сохранение уровня
на внешней линии во время намеренного освобождения без согласования схемы.
В данной лабораторной AF вообще не используются, кроме неизменяемой отладки.

LCKR проверяется; программная установка блокировки не реализована и для
лабораторной не требуется. Разблокировать аппаратную блокировку обычной
записью нельзя, нужен сброс. Тестовый стенд тестов не симулирует протокол LCKR:
он лишь задаёт состояние «заблокировано» для проверки отказа драйвера.

## Отличия от HAL и LL

HAL_GPIO_Init использует GPIO_InitTypeDef и обрабатывает также режимы EXTI.
HAL_GPIO_ReadPin/WritePin/TogglePin дают стандартный API одиночных операций;
сами операции HAL GPIO не требуют блокирующих задержек. Нельзя утверждать,
что HAL по определению блокирующий или что он не использует BSRR.

LL предоставляет тонкие функции/макросы доступа к полям регистров и тоже
может использовать BSRR. Собственный драйвер здесь не вызывает ни HAL GPIO,
ни LL GPIO. GPIO_TypeDef и определения адресов взяты из CMSIS (это разрешено
заданием), IoConfig/IoResult и алгоритмы доступа разработаны самостоятельно.
Есть единая масочная запись смешанных 0/1, чтение текущей конфигурации, явная
проверка LCKR и отказ от неподготовленной передачи активного AF. Никакого EXTI.

RMW конфигурационных регистров рассчитан на единственный контекст main.
SysTick изменяет только время. Атомарность BSRR не делает остальные операции
конфигурации потокобезопасными; конкурентную настройку из ISR API не обещает.

Для изучения HAL см. `Drivers/STM32F4xx_HAL_Driver/Src/stm32f4xx_hal_gpio.c`
и соответствующий `.h`. В проекте нет сгенерированного gpio.c: роль настройки
выполняют `led_init`, `io_clock_enable`, `io_configure` в main.
