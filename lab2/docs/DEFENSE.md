# Материалы для защиты

## Регистры USART

| Регистр / поля | Назначение в работе |
|---|---|
| SR: RXNE | В DR есть принятый байт; нужно прочитать до следующего кадра |
| SR: TXE | Регистр передачи пуст; можно записать следующий байт |
| SR: TC | Завершены и DR, и сдвиговый регистр: последний стоп-бит отправлен |
| SR: ORE, FE, NE, PE | Переполнение, ошибка стоп-бита, шум, ошибка чётности |
| DR | Чтение приёмного / запись передающего регистра |
| BRR | Делитель скорости: мантисса и дробная часть |
| CR1: UE, TE, RE | Включить USART, передатчик, приёмник |
| CR1: M, PCE, PS | Размер слова и чётность; для 8N1 обнулены |
| CR1: OVER8 | Выбор oversampling; здесь 16, OVER8=0 |
| CR1: RXNEIE, TXEIE, TCIE, PEIE | Источники прерываний приёма, передачи, чётности |
| CR2: STOP | Количество стоп-битов; здесь 1 |
| CR3: EIE | Прерывания ошибок линии |
| CR3: RTSE, CTSE, DMAR, DMAT | Flow control и DMA; здесь отключены |

TXE и TC различаются: TXE разрешает загрузить следующий байт ещё во время отправки
предыдущего кадра, TC означает завершение на линии. Переключение режима ждёт TC,
чтобы не оборвать последний ответ. Собственный драйвер передаёт по одному байту
и использует TC callback, что упрощает управление очередью, но не максимизирует
пропускную способность по сравнению с передачей блоками по TXE/DMA.

Чтение SR, затем DR сбрасывает ORE/FE/NE/PE и RXNE. Ошибка регистрируется счётчиком,
приём продолжается. Программная очередь не может восстановить байт, уже потерянный
при аппаратном ORE. В HAL версии очистка и обработка выполняются через HAL макросы
и HAL_UART_IRQHandler / ErrorCallback.

## NVIC и прерывания

Для вызова обработчика должны совпасть событие периферии, её разрешающий бит,
разрешение IRQ в NVIC и отсутствие маскировки процессором. Вектор USART6_IRQHandler
содержится в startup; приложение определяет его сильную реализацию вместо weak.
Обработчик вызывает транспорт и callbacks, а команды разбираются в основном цикле.

ISER включает IRQ, ICER отключает, ISPR/ICPR устанавливает/снимает pending,
IABR показывает активное прерывание, IPR задаёт приоритет. Меньшее число приоритета
означает более высокий приоритет. В проекте SysTick имеет приоритет 0, USART6 — 5.
NVIC поддерживает вложенность: более приоритетное событие может прервать обработчик.
При HAL_Init установлена группировка NVIC_PRIORITYGROUP_4.

Критическая секция сохраняет PRIMASK, запрещает маскируемые прерывания,
меняет общие индексы/счётчики и восстанавливает прежний PRIMASK.
Одного volatile недостаточно: он не делает операцию read-modify-write атомарной.
FIFO вызывается одновременно из foreground и ISR, поэтому защита необходима.
Не следует безусловно вызывать __enable_irq после секции: вызывающий код мог уже
держать прерывания выключенными. Длинные критические секции повышают риск ORE.

В P выключается именно USART6 IRQ, а также источники прерываний UART.
SysTick остаётся включённым для светофора, дребезга и HAL timeouts.
Отключение NVIC без отключения источников могло бы оставить IRQ pending.

## Отличия собственной реализации от HAL и LL

| Свойство | Собственный UART | HAL UART | LL USART |
|---|---|---|---|
| Состояние | RegisterUart + общие очереди | UART_HandleTypeDef, Lock, gState, RxState, ErrorCode | Обычно состояние хранит приложение |
| Настройка | Прямые записи RCC/GPIO/USART | HAL_UART_Init и MSP callback | Функции/inline для отдельных полей регистров |
| Обмен | Свои проверки SR, DR и обработчик | Blocking, IT, DMA и callbacks | Низкоуровневые операции; автомат обмена строит приложение |
| Буферизация | Универсальные RX/TX FIFO в оболочке | Пользовательский буфер одной операции, не очередь сообщений | Прикладные буферы не организует |
| Режимы | Только нужные 57600 8N1, USART6 | Множество вариантов UART, чётность, DMA, callbacks и др. | Более широкий набор регистровых операций |
| Обработка ошибок | Счётчики и SR→DR | ErrorCode, завершение/продолжение RX, ErrorCallback | Проверка/очистка флагов на усмотрение приложения |

HAL_UART_Transmit_IT сам по себе не является FIFO: нельзя передавать указатель
на временный буфер или вызывать новую передачу, пока HAL занят. Здесь данные копируются
в TX очередь, а один байт находится в статическом staging-хранилище до callback.
Вызов uart_write означает принятие в очередь, а не доставку на линию.
UART_FULL означает, что весь запрос отклонён, поэтому повтор не дублирует часть данных.

Прямые записи регистров не делают собственный драйвер эквивалентом LL:
в проекте нет вызовов LL_USART_*, структуры состояния, FIFO и автомат обмена написаны
самостоятельно. CMSIS используется для определения адресов и NVIC; это не HAL UART/LL USART.
Проверка nm в build.py удостоверяет отсутствие стандартных UART-функций в части 2.

## Источники для подготовки

- [RM0090, USART](https://www.st.com/resource/en/reference_manual/rm0090-stm32f407-advanced-armbased-32bit-mcus-stmicroelectronics.pdf): устройство USART, SR/DR/BRR/CR1–CR3, ошибки и последовательность настройки.
- [PM0214, NVIC](https://www.st.com/resource/en/programming_manual/DM00046982-.pdf): разрешение, pending, приоритеты, маскирование и вложенность прерываний.
- [Исходник стандартного HAL UART](../Drivers/STM32F4xx_HAL_Driver/Src/stm32f4xx_hal_uart.c).
- [Схема SDK-1.1M](../../lab1/docs/SDK1.1M.pdf), страницы PDF 2 и 3.

Стандартный usart.c/.h обычно содержит UART_HandleTypeDef, MX_USARTx_UART_Init
и объявления. MSP задаёт RCC/GPIO/NVIC, а stm32f4xx_it.c вызывает HAL_UART_IRQHandler.
Здесь эти обязанности распределены между uart_hal.c, main.c и startup; в регистровой
конфигурации UART не инициализируется генератором.
