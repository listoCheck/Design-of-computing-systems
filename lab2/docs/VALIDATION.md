# Проверки лабораторной № 2

Дата программной проверки: 11.10.2026. Микроконтроллер не подключён.

## Выполнено без стенда

```text
python lab2/tools/build.py
HAL:      text 13288, data 120, bss 2896 bytes
Register: text 10204, data 120, bss 2832 bytes

python lab2/tests/run_tests.py
PASS hal: 787 ARM C assertions; UART TX order checked.
PASS register: 787 ARM C assertions; UART TX order checked.
```

ARM GCC 10.3 из STM32CubeIDE 1.9.0. Сборка использует `-Wall -Wextra -Werror`.
Для сторонних исходников отключено только предупреждение unused-parameter.
В register ELF отсутствуют HAL_UART_* и LL_USART_*: build.py проверяет nm автоматически.
Тесты используют маленькие очереди RX=8/TX=8, что позволяет быстро проверить заполнение
и циклическое переиспользование. Прошивка по умолчанию использует RX=256/TX=256.

Дополнительно успешно собраны обе прошивки с `--polling --rx-size 7 --tx-size 11`:
начальный режим P и ёмкости, не являющиеся степенями двойки.
После проверки восстановлены сборки с настройками по умолчанию.

Проект также импортирован и собран **самим STM32CubeIDE в консольном режиме**:
конфигурации Debug и Release создали `Debug/lab2.elf` и `Release/lab2.elf`.
Проверка символов подтвердила HAL UART только в Debug и отсутствие его в Release.
Журнал консольной сборки — `lab2/build/cubeide-build.log`.
Проверены XML `.project`/`.cproject` и все локальные ссылки документации.

| Область | Проверенные сценарии |
|---|---|
| FIFO | Пустая/полная очередь, peek, порядок, многократный обход кольца |
| TX | Не принимает запрос при заполнении; AB/XYZ/ffffffff выходят по порядку |
| RX | EMPTY немедленно; чтение байта, очередь, переполнение и счётчик |
| UART | BRR, AF8, выключение источников и NVIC в P, включение в I |
| Переключение | BUSY во время TX, сохранение RX, I→P→I |
| Ошибки | ORE и восстановление приёма следующего байта |
| Команды | Все команды варианта, I/P в ответе, неизвестная команда |
| Ввод | CR, LF, CRLF, Backspace, длинная строка, embedded NUL |
| Timeout | 0, отрицательное, нечисловое, верхняя граница и переполнение числа |
| Светофор | Все фазы, мигание, сокращение красного, игнорирование/запоминание кнопки |
| Время | Переполнение uint32 tick, подавление дребезга и удержание |
| Вывод | Проверка backpressure прикладного буфера |

Исполняется настоящий C-код ARM, включая поставляемый HAL UART.
Unicorn-модель воспроизводит только минимальные эффекты DR/SR и ICER/ISER.
Готовность TX в модели немедленная, IRQ вызываются тестом вручную; электрическая
линия, тактовая погрешность, вложенность и реальные гонки периферии не моделируются.
Полный запуск main на физическом STM32 этими проверками не заменяется.
Результаты каждого запуска сохраняются в `lab2/build/test-results.txt`.

## План аппаратной проверки после подключения

Выполнить для HAL и register ELF, в каждом случае в I и P:

1. Подключить питание/DBG USB, прошить нужный ELF. Открыть UART COM-порт в PuTTY:
   57600, 8N1, flow control None, local echo Off.
2. Проверить приветствие и эхо каждого символа. Отправить `?` с Enter;
   убедиться в наличии фазы, mode 1, timeout 12 и I/P.
3. Проследить последовательность светодиодов и длительность фаз без остановок отладчика.
4. В mode 1 проверить сокращение красного, игнорирование кнопки на зелёном и
   запоминание на мигающем зелёном/жёлтом; удержание не должно повторять события.
5. Отправить `set mode 2`, дождаться OK. Кнопка не влияет на цикл. Вернуть mode 1.
6. Отправить `set timeout 20`, проверить OK и новый красный период.
   Отправить `set timeout 0`, `set mode 3`, длинную строку: получить ошибки,
   затем проверить восстановление `?`.
7. Переключить interrupts off, затем `?` должен содержать P. В отладчике проверить
   отсутствие разрешения USART6 IRQ в NVIC и битов RXNEIE/TCIE/TXEIE/PEIE/EIE.
   SysTick продолжает работать. Переключить on, проверить I и корректный ответ.
8. Повторить переключения, контролируя lab2_fault, uart_state и целостность вывода.
9. При наличии логического анализатора измерить период бита (~17,36 мкс),
   старт/стоп, отсутствие чётности и кадры 8N1; отдельно оценить реальную погрешность HSI.
10. Провести ограниченный нагрузочный тест с контролем rx_overflow/hardware_errors.
    Данные сверх ёмкости FIFO не должны теряться незаметно; TX_FULL должен вызывать
    повтор у отправителя, а не безусловное отбрасывание.

Эти пункты пока **не выполнены**. Аппаратных логов и результатов прошивки нет.
