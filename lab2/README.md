# Лабораторная работа 2. Последовательный интерфейс UART

Вариант 1 «Светофор», стенд SDK-1.1M (STM32F427). Реализованы обе части:

- Часть 1: драйвер поверх STM32 HAL, приём и передача в режимах прерываний и опроса.
- Часть 2, способ 1: собственный регистровый драйвер, внедрённый в то же приложение.

Обе версии поддерживают одинаковые команды и переключение I/P во время работы.
Подключение микроконтроллера **не требуется для сборки и программных тестов**.
Проверка на физическом стенде пока не выполнена.

## Сборка без платы

В корне репозитория:

```powershell
python lab2/tools/build.py
```

Создаются `lab2/build/hal/lab2.elf` и `.bin` для части 1,
`lab2/build/register/lab2.elf` и `.bin` для части 2.
Используется ARM GCC из установленного STM32CubeIDE (`C:/ST`),
либо из `PATH` / переменной `ARM_GCC_BIN`. Доступ к сети не требуется.

```powershell
python lab2/tools/build.py --backend hal --polling --rx-size 128 --tx-size 64
python lab2/tools/build.py --backend register
```

`--polling` задаёт режим P при старте; без этого ключа стартовый режим I.
Режим затем можно изменить командами. Размеры очередей задаются при компиляции,
допускаются любые положительные значения, включая не степени двойки.
Повторная сборка перезаписывает результаты выбранного backend.

## STM32CubeIDE

1. `File → Import → General → Existing Projects into Workspace`, выбрать папку `lab2`.
2. Не включать `Copy projects into workspace`.
3. `Project → Build Configurations → Set Active`:
   `Debug` — HAL (часть 1), `Release` — регистровый UART (часть 2).
4. `Project → Build Project`. Результат: `Debug/lab2.elf` либо `Release/lab2.elf`.

Файл `.ioc` отсутствует: все настройки выполняются кодом, CubeMX не нужен.
`UART_BACKEND_REG=1` задан в Release; UART HAL в этой конфигурации отключён.
Для размера очередей добавить `UART_RX_CAPACITY=...` и `UART_TX_CAPACITY=...`
в `C/C++ Build → Settings → MCU GCC Compiler → Preprocessor`.
`UART_START_INTERRUPTS=0` задаёт начальный режим P.
Проверены собственный скрипт сборки и консольная сборка Debug/Release самим CubeIDE.
Запуск GUI CubeIDE не выполнялся. При консольном импорте на Windows использовать
`-import file:///C:/.../lab2`, а папку workspace размещать вне папки `lab2`.

## Протокол и команды

UART: **57600 бит/с, 8 бит, без чётности, 1 стоп-бит, без flow control**.
Команда завершается Enter: CR, LF или CRLF. Регистр и пробелы значимы.
Каждый полученный байт возвращается как эхо; ответ начинается с новой строки
и заканчивается CRLF. В терминале отключить Local echo, чтобы символы не дублировались.
CRLF выполняет команду один раз; LF после CR также возвращается как эхо.

| Команда | Действие / ответ |
|---|---|
| `?` | Например: `red, mode 1, timeout 12, I` |
| `set mode 1` | Обрабатывать кнопку; `OK` |
| `set mode 2` | Игнорировать кнопку и сбросить сохранённый запрос; `OK` |
| `set timeout X` | Красный период X секунд; `OK` |
| `set interrupts on` | Перейти в I после отправки `OK` |
| `set interrupts off` | Перейти в P после отправки `OK` |
| Другая команда | `ERROR: unsupported command` |

Начальные настройки: mode 1, timeout 12 секунд, I (если не задан `--polling`).
В `?` возможны `red`, `yellow`, `green`, `blinking green`. При мигании выводится
название фазы `blinking green`, в том числе в полупериоде с погашенным светодиодом.
X — целое число 1..2147483, без знака и дробной части. Некорректный X вызывает
`ERROR: timeout must be 1..2147483 seconds`, настройки сохраняются.
Команды длиннее 79 символов и содержащие управляющие символы, кроме Enter/Backspace,
отклоняются: `ERROR: command too long`. После Enter приём следующей строки восстанавливается.

## Логика светофора

Красный X секунд → зелёный 3 секунды → мигающий зелёный 3 секунды
(переключение каждые 500 мс) → жёлтый 1 секунду → красный.
`set timeout` изменяет именно красный период; остальные периоды сохранены из `lab1`.
Новая величина применяется к текущему красному периоду без перезапуска отсчёта.
Если прошедшее время уже больше нового периода, переход произойдёт в следующем цикле.

В mode 1 кнопка сокращает красный до X/4 от его начала. Во время обычного зелёного
нажатие игнорируется; при мигающем зелёном или жёлтом запоминается до ближайшего
красного. Повторное нажатие не перезапускает время. Mode 2 отключает эту обработку.
Подавление дребезга — 30 мс, удержание не порождает повторных событий.

## Подключение, когда стенд будет доступен

| Сигнал | Назначение |
|---|---|
| USART6 TX | PC6, AF8 |
| USART6 RX | PC7, AF8 |
| Зелёный | PD13 |
| Двухцветный: красный / жёлтый | PD15 / PD14 |
| Кнопка nBTN | PC15, активный 0, внешняя подтяжка |

Разводка сверена по [схеме](../lab1/docs/SDK1.1M.pdf), страницы PDF 2 и 3,
и [примеру SDK_UART производителя](https://github.com/lmtspbru/SDK-1.1M/tree/bd8cba8f4bd5fc2d1460e6ad4da7b7dd13d9e14d/SDK_UART).
Частоты HSI/AHB/APB1/APB2 — 16 МГц, PLL выключен.

Подключить питание и **DBG USB**. Стенд использует FT2232/JTAG для прошивки
и отдельный канал UART (Interface 1) для COM-порта. Не заменять драйвер UART
драйвером WinUSB. Настройка отладочного адаптера описана в [lab1](../lab1/README.md),
готовый OpenOCD script — `SDK11M.cfg`.

Прошивка после подключения, из корня репозитория:

```powershell
python lab1/tools/board.py flash --elf lab2/build/hal/lab2.elf
# Для части 2:
python lab1/tools/board.py flash --elf lab2/build/register/lab2.elf
```

Затем открыть COM-порт в PuTTY (Serial) с указанными выше параметрами.
Вводить команды по одной, ожидая ответ. Не подключать второй терминал к тому же порту.
Сейчас эти аппаратные команды не выполнялись: микроконтроллер не подключён.

## Тесты и оформление

```powershell
python lab2/tests/run_tests.py
```

Нужен Python-пакет `unicorn`: `python -m pip install unicorn`.
Если доступна существующая `.lab1-tools`, тесты используют её без установки.
Исполняется скомпилированный C-код ARM с настоящими реализациями обоих драйверов,
включая стандартный HAL UART. Эмуляция моделирует минимальные эффекты SR/DR и NVIC;
электрические сигналы и реальное время линии не моделируются.

- [Отчёт](docs/REPORT.md) — цели, реализация, соответствие требованиям и выводы.
- [Материалы для защиты](docs/DEFENSE.md) — UART, регистры, NVIC, сравнение HAL/LL.
- [Проверки](docs/VALIDATION.md) — результаты без платы и аппаратный чек-лист.
- [Источники и лицензии](docs/THIRD_PARTY.md).

Основные файлы: `queue.c` — общая очередь; `uart_driver.c` — буферизация и API;
`uart_hal.c` / `uart_register.c` — две реализации транспорта;
`console.c` — команды и эхо; `traffic.c` — светофор; `main.c` — цикл приложения.
Очереди не содержат команд, цветов, тайм-аутов или иной прикладной логики.

### Ограничения буферизации

`uart_write` возвращает `UART_FULL` без принятия данных, когда места недостаточно.
Приложение сохраняет неподтверждённый вывод и повторяет передачу в следующих циклах.
`uart_read` возвращает `UART_EMPTY` сразу при отсутствии данных.
RX при заполнении очереди отбрасывает новый байт и увеличивает `rx_overflow`.
Ошибки линии учитываются в `hardware_errors`, ошибки запуска TX — в `tx_errors`.
Состояние доступно через `uart_state()`; это также удобно для отладчика.

Конечная очередь снижает вероятность случайной потери данных, но не обеспечивает
приём бесконечного потока без потерь. В режиме P отсутствие достаточно частого опроса
может привести к ORE. Для интерактивных команд следует ждать ответа перед следующей
командой; при нагрузочном тесте контролировать счётчики. Прерывания SysTick работают
в обоих режимах; в P запрещены именно прерывания USART6.
